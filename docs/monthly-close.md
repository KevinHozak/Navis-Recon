# Overview attention and monthly close

The overview preserves signed native-unit balances. The allocation pie shows positive asset balances only, including cash and otherwise uncategorized assets. Its text table separately exposes negative offsets and reconciles them to signed total assets. A positive liability balance is a credit/refund; it is never turned into debt by taking an absolute value.

Financial attention reads sync outcomes, statement sequence anomalies, pending ledger reviews, obligation alerts and expiration radar independently. Each source has its own successful-read timestamp and current, loading, unavailable or stale state. Failed refreshes retain visibly stale items. An empty queue is healthy only when every source read succeeded. Statement sequence gaps are catalog heuristics, not proof that every account has all statements. Buttons navigate to the corresponding institution, pending queue, import operation, renewal or record.

Persisted actions invalidate affected resources through a shared event boundary, including uncertain IPC failures. Overview items and sidebar badges use the same attention snapshots. Confirmed imports and terminal sync events refresh attention; persisted approval changes also refresh ledger totals. Periodic and focus checks detect changes made outside the app. Background catalog refreshes preserve the mounted filter controls. Navigation moves keyboard focus to the content region, while attention refreshes preserve stable item buttons.

## Close policy

Select an ended calendar month and an explicit currency/unit. Month-end eligibility uses the backend's UTC date, as do existing renewal/radar calculations; transaction dates remain the ledger's written dates. Period metrics cover all ledger accounts in that native unit; there is no implicit FX conversion. Every asset/liability account appearing in the ledger through the period end, plus overlapping mapped statement accounts, must be selected for statement evidence or have an explicit scope exception. At least one account must require statements. Scope exceptions require a meaningful explanation and are retained verbatim in the private summary; they are reviewer attestations about excluded statement coverage, not verified balances. An account with overlapping mapped statement evidence must be reconciled rather than waived through an exception.

For every selected account, current reconciled statement periods must continuously cover the entire calendar month. A single statement ending mid-month cannot close that month. Adjacent or overlapping statement periods can cover it together, including statement cycles crossing month boundaries. All overlapping mapped evidence for selected accounts must be reconciled against the current ledger revision, have unchanged PDF bytes, satisfy the existing zero-difference/matched-transaction reconciliation policy, and be readable inside the configured statement archive. Legacy checklist booleans do not satisfy these requirements.

Active sync analysis/review/import, non-success durable import outcomes (including unavailable recovery storage), pending selected-unit entries through the period end, missing account scope, incomplete statement coverage, unavailable metrics or unexplained movement block closing. Blockers identify a workflow stage, a household reviewer owner and a resolution view. The month and draft scope remain mounted while visiting resolution views.

## Persistence and freshness

The native commands `get_monthly_close` and `save_monthly_close` use private, per-ledger Windows application data beside the existing reconciliation store: `monthly-close.json`. This location is rejected when its resolved existing ancestry is in Git. Reparse ancestry checks apply to evidence paths. Summaries are never automatically published or added to the repository.

Each close/reopen appends history with the selected scope and its exceptions, exact period metrics, statement references and SHA-256 identities, ledger revision, reconciliation-store revision, sync-outcome revision, unresolved blockers and timestamp. A successful close has no unresolved blockers. Reopening retains prior close evidence and can record the blockers now present.

Saving requires both the observed document revision and evidence fingerprint. The close store and reconciliation store use cooperative exclusive sidecar locks. Ledger/PDF read handles deny writing and deletion throughout validation/publication but allow other financial views to read the same stable files. Document publication uses atomic replacement with readback. External cooperative writers cannot change those sources while the close is saved; arbitrary non-cooperating JSON writers remain outside the sidecar-locking contract. A lost IPC reply is reconciled by reading actual state, never by automatically repeating the save.

A changed ledger, reconciliation document, statement bytes, scope, import outcome or close eligibility makes the retained close stale. Checks run after relevant persisted actions, on focus and periodically. Whole-ledger revision changes conservatively invalidate a close even when an edit concerns another period. Loading a saved scope explicitly rechecks it against current evidence; it does not restore old source authority.

## Synthetic verification

Rust tests exercise a complete exact-metric close and readback, private statement provenance, reopen history, blocked missing coverage, pending reviews, failed/active imports, partial statement periods, explicit uncovered-account scope, changed PDF/ledger revisions and stale-proof rejection without changing the ledger. Shared-PDF account mappings retain one locked evidence handle, and mapped evidence cannot be waived by a scope exception. Frontend controller and IPC tests cover independent freshness, source failures, response generations, filtered destinations, shared invalidation, duplicate-save prevention, uncertain-save readback and changes arriving during a save.

Rendered acceptance used a bundled synthetic app and an isolated headless browser, with all requests fulfilled from local test assets and all IPC mocked. Observed passes: signed debt/refund values, exact allocation reconciliation, cyan accent, record/renewal/import/institution filters, pending-review approval invalidation, keyboard content focus, attention refresh focus retention, draft month scope across navigation, closing, changed-evidence staleness, disabled reclose, reopening and visible stale-source errors. A focused final browser check also held older renewal/catalog responses across newer resource invalidations: newer rows persisted, old responses were ignored, and search focus/filter values survived both refreshes. No uncaught browser errors remained. The temporary harness and bundles were removed after verification; the native file-backed scenarios above independently verify actual persistence.
